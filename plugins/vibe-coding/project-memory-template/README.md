# Project Memory — Template

## What This Is
Project Memory is the shared context layer for all Vibe Coding skills. Every skill checks for a `project-memory/` directory in **your project root** and adapts its output based on accumulated project decisions.

This folder contains **empty templates**. You don't need to copy these manually — skills will scaffold them automatically when you run them.

## How It Works

```
your-project/              <- your working directory
├── project-memory/        <- created automatically by skills
│   ├── project-context.md <- written by /vibe-coding:discovery
│   ├── ux-spec.md         <- written by /vibe-coding:discovery
│   ├── mvp-scope.md       <- written by /vibe-coding:mvp-scope
│   ├── design-tokens.md   <- written by /vibe-coding:design-system
│   └── learnings.md       <- updated after iterations
├── prompts/               <- generated by /vibe-coding:prompt-generator
│   ├── page-01-landing.md
│   ├── page-02-dashboard.md
│   └── ...
└── ...
```

## Quickstart

1. Open your project in Claude Code
2. Run `/vibe-coding:orchestrator` — it scans for gaps and tells you what to do first
3. Run `/vibe-coding:discovery` — creates `project-memory/project-context.md` and `ux-spec.md`
4. Run `/vibe-coding:mvp-scope` — creates `project-memory/mvp-scope.md`
5. Run `/vibe-coding:design-system` — creates `project-memory/design-tokens.md`
6. Run `/vibe-coding:prompt-generator` — generates coding agent prompts in `prompts/`
7. All skills automatically read project-memory and maintain consistency

## How Skills Use Project Memory
- **Discovery** writes `project-context.md` and `ux-spec.md`
- **MVP Scope** reads context + ux-spec, writes `mvp-scope.md`
- **Design System** reads all above, writes `design-tokens.md`
- **Prompt Generator** reads all above, generates coding agent prompts
- **Prompt Craft** reads `project-context.md` for service context
- **Service Spec** reads all above, generates final service documentation
