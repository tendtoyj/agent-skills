# AI 요약본 정확성 검증 가이드라인 (verify_accuracy.txt)

## 1. 목적 (Purpose)

본 가이드라인은 AI가 생성한 요약 보고서(이하 '요약본') 내용의 사실 및 수치 정확성을 원본 보고서와 비교하여 검증하고, 원본에 근거하지 않은 내용(환각)을 식별하는 것을 목적으로 한다. 이 검증은 요약본 정보의 신뢰도를 높여 사용자가 잘못된 정보에 기반한 판단을 내리는 것을 방지하기 위해 수행된다.

## 2. 검증 대상 및 범위 (Scope)

* **검증 대상:** 사용자가 제공한 원본 보고서 세트와 해당 보고서들을 기반으로 AI가 생성한 요약본 세트이다.
* **비교 방법:** 검증은 각 요약본과 해당 원본 보고서를 **1:1로 매칭**하여 수행한다. 여러 보고서 내용을 혼합하여 검증하지 않는다.
* **검증 범위 (In Scope):**
    * 검증 범위는 **오직 요약본에 명시적으로 포함된 내용**에 한정된다.
    * 요약본에 기술된 수치 (값, 비율, 통계 등), 날짜, 고유명사 (인명, 지명, 제품명 등), 사건, 결과, 핵심 결론 등 **사실 관계 정보의 정확성**을 원본과 대조한다.
* **검증 제외 범위 (Out of Scope):**
    * **요약본에 포함되지 않은 정보(누락 정보)는 본 정확성 검증의 대상이 아니다.**
    * 요약의 적절성, 완전성, 중요도 판단, 문체 등 내용의 질적인 측면은 평가하지 않는다. 오직 사실과 수치의 일치 여부만 확인한다.

## 3. 검증 원칙 (Principles)

검증 수행 및 결과 보고 시 다음 원칙을 반드시 준수해야 한다.

* **객관성 (Objectivity):** 어떠한 주관적 해석이나 판단 없이, 원본과 요약본 간의 객관적인 사실 불일치만을 기록한다. '잘못되었다', '틀렸다' 등의 가치 판단 표현보다는 '불일치함', '다름' 등으로 서술한다.
* **명확성 (Clarity):** 어떤 보고서/요약본 쌍에서 어떤 내용에 불일치가 발견되었는지 구체적이고 명확하게 기술한다. 모호한 표현을 지양한다.
* **비교 제시 (Side-by-Side Comparison):** 불일치가 발견된 경우, 독자가 차이점을 명확히 인지할 수 있도록 요약본의 해당 내용과 원본 보고서의 관련 내용을 **반드시 함께 제시**한다.
* **근거 명시 (Source Citation):** 원본 보고서에서 불일치의 근거나 올바른 정보를 찾을 수 있는 경우, 해당 위치(예: 섹션 제목, 페이지 번호, 문단 번호 등)를 가능한 명시하여 신뢰도를 높인다.
* **오류 유형 구분 (Error Typing):** 발견된 불일치의 유형을 명확히 구분하여 기록한다. (상세 유형은 '6. 불일치/오류 유형 정의' 참조)
* **수치 검증의 코드 기반 원칙 (Code-Based Numerical Verification):** 요약본에 포함된 **모든 수치 정보(금액, 비율, 증감률, 합계, 평균, 순위 등)는 반드시 Python 코드를 실행하여 검증**한다. 텍스트 수준의 눈대중 비교만으로 수치 정확성을 판단해서는 안 된다.

## 4. 검증 절차 (Procedure)

1.  **자료 준비:** 검증 대상인 각 요약본과 그에 대응하는 원본 보고서를 준비한다.
2.  **내용 대조:** 요약본의 내용을 문장 또는 핵심 정보 단위로 나누어 검토하며, 원본 보고서에서 해당 내용의 사실 및 수치 정확성을 확인한다.
3.  **수치 항목 Python 코드 검증:** 요약본에서 수치가 포함된 항목을 식별하면 다음 절차를 수행한다.
    * **(3-a) 원본 데이터 추출:** 원본 보고서에서 해당 수치의 근거가 되는 원시 데이터(raw data)를 식별하고 Python 변수로 정의한다.
    * **(3-b) 재계산 코드 작성 및 실행:** 요약본에 제시된 수치를 도출하기 위한 계산 로직(합계, 평균, 증감률, 비율, 전기 대비 변화율 등)을 Python 코드로 작성하고 **실제로 실행**한다.
    * **(3-c) 결과 대조:** 코드 실행 결과값과 요약본에 기재된 수치를 비교한다. 불일치가 발견되면 코드 실행 결과를 근거로 기록한다.
    * **(3-d) 검증 대상 수치 유형 예시:**
        * 절대값: 매출액, 비용, 이익, 건수, 인원 등
        * 비율/퍼센트: 성장률, 달성률, 점유율, 전환율, 이탈률 등
        * 증감: 전월/전기/전년 대비 변화량 및 변화율
        * 파생값: 합계, 평균, 가중평균, 순위, 누적값 등
        * 복합 계산: 여러 원본 데이터를 조합하여 산출된 수치
4.  **사실 항목 텍스트 대조:** 수치가 아닌 사실 관계 정보(고유명사, 날짜, 사건, 인과 관계 등)는 원본 보고서 텍스트와 직접 대조하여 정확성을 확인한다.
5.  **불일치 식별:** 원본과 다르거나, 원본에서 해당 내용의 근거를 찾을 수 없는 경우(환각)를 식별한다.
6.  **결과 기록:** 식별된 모든 불일치/오류 사항을 아래 '5. 결과 보고서 구조 및 형식'에 따라 상세히 기록한다. **수치 오류의 경우, Python 코드로 재계산한 정확한 값을 '원본 내용' 열에 함께 명시**한다.

## 5. 결과 보고서 구조 및 형식 (Output Structure & Format)

검증 결과는 아래 구조와 형식 지침에 따라 **마크다운(Markdown)** 형식으로 작성한다.

* **전체 구조:**
    ```markdown
    # AI 요약본 정확성 검증 결과 보고서

    ## 1. 검토 개요
    * 검토 대상 원본 보고서: N건
    * 검토 대상 AI 요약본: N건
    * 주요 검토 항목: [예: 주요 수치, 핵심 결과, 고유명사 등]
    * 수치 검증 방법: Python 코드 실행을 통한 원본 데이터 기반 재계산 대조
    * 발견된 주요 오류 유형: [예: 수치 오류, 사실 오류 등]

    ## 2. 보고서별 검토 결과 요약
    * **보고서 1: [원본 보고서 제목 또는 식별자]**
        * 발견된 불일치/오류 건수: X건
        * 전반적 정확성 평가: [예: 대체로 정확함 / 일부 수치 오류 발견됨 / 사실 관계 오류 다수 등]
    * **보고서 2: [원본 보고서 제목 또는 식별자]**
        * 발견된 불일치/오류 건수: Y건
        * 전반적 정확성 평가: [...]
    * ... (나머지 보고서에 대해 반복)

    ## 3. 상세 불일치/오류 목록

    | 보고서 ID | 오류 위치 (요약본 내) | 요약본 내용 | 원본 내용 (또는 근거 없음) | 오류 유형 | 검증 방법 | 원본 근거 위치 (선택) |
    |---|---|---|---|---|---|---|
    | 보고서 1 | 섹션 2, 3번째 문장 | 매출액 150억 달성 | 매출액 130억 (Python 재계산: 130.2억) | 수치 오류 | Python 코드 | 보고서 본문 p.5 |
    | 보고서 1 | 핵심 요약 1번 항목 | 전년 대비 25% 성장 | 전년 대비 18.7% 성장 (Python 재계산: 130.2/109.7=18.7%) | 수치 오류 | Python 코드 | 보고서 본문 p.3, p.5 |
    | 보고서 1 | 핵심 요약 2번 항목 | 신제품 'Alpha' 출시 | 신제품 'Beta' 출시 | 사실 오류 | 텍스트 대조 | 보고서 요약 p.2 |
    | 보고서 2 | 결론 섹션 | 경쟁사 C 진입 확인 | (원본에서 관련 내용 찾을 수 없음) | 환각 | 텍스트 대조 | - |
    | ... | ... | ... | ... | ... | ... | ... |

    ## 4. (선택) 시사점 및 제언
    * [예: 특정 유형의 수치(예: %)에서 오류가 자주 발생하는 경향 발견]
    * [예: 향후 요약 시 고유명사 정확성 교차 확인 필요]
    ```

* **형식 지침:**
    * 마크다운 헤더(`#`, `##`, `###`), 불릿 포인트(`*`, `-`), 표(`|---|---|`)를 적극 활용하여 구조화하고 가독성을 높인다.
    * **상세 불일치/오류 목록은 반드시 표(Table) 형식을 사용한다.**
    * **'검증 방법' 열을 포함하여, 해당 항목이 Python 코드로 검증되었는지 텍스트 대조로 검증되었는지 명시한다.**
    * 모든 내용은 불필요한 수식어나 설명을 배제하고 간결하고 명료하게 작성한다.

## 6. 불일치/오류 유형 정의 (Error Type Definitions)

검증 시 발견되는 불일치는 다음 유형으로 구분하여 기록한다.

* **수치 오류 (Numerical Error):** 요약본에 제시된 숫자, 값, 비율, 통계 등이 원본 보고서의 해당 수치와 일치하지 않는 경우. **반드시 Python 코드를 실행하여 검증한다.** (예: `150억` vs `130억`, `25% 증가` vs `15% 증가`)
* **사실 오류 (Factual Error):** 요약본에 기술된 사실(고유명사, 날짜, 사건 내용, 인과 관계, 결과 등)이 원본 보고서의 내용과 다른 경우. (예: 제품명 'Alpha' vs 'Beta', 'A 부서 담당' vs 'B 부서 담당')
* **환각 (Hallucination):** 요약본에 기술된 내용이 원본 보고서에서 전혀 근거를 찾을 수 없는 경우. AI가 정보를 잘못 연결하거나 생성한 것으로 추정될 때 해당한다.
* **(필요시 추가 정의 가능)** 기타 명확히 구분되는 오류 유형이 있다면 정의하여 사용할 수 있다. (예: 인용 오류 - 원본의 특정 부분 인용 시 내용 왜곡 등)
